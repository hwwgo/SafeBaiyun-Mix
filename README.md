# 🔓 SafeBaiyun Mix

> **基于 [SafeBaiyun](https://github.com/dogproton/SafeBaiyun) 和 [SafeBaiyun-Mix](https://github.com/yotong-max/SafeBaiyun-Mix) 的二次开发版本**
>
> 更多门 · 更快传 · 更智能 · 更好用

广州市白云区蓝牙门禁「平安回家」离线版本。

本项目在原版 **SafeBaiyun** 的基础上，由 [yotong-max/SafeBaiyun-Mix](https://github.com/yotong-max/SafeBaiyun-Mix) 进一步扩展，并在此基础上继续增加和优化了多门禁管理、**探测开锁合并**、一键开锁、开锁状态反馈、参数调节以及 UI 交互等功能。

无需网络连接，只需门禁 MAC 地址和加密 Key，即可通过手机蓝牙 BLE 离线开门。

## 🆕 本项目特色功能

### 🔄 一键开锁（探测 + 轮询）

这是本项目比较核心的增强功能。

当你有多个门禁，但不确定当前所在位置对应的是哪一个门禁时，可以选择多个门禁进行一键开锁。

程序分为**两个独立阶段**：

#### 阶段一：探测（快速找附近的）

按顺序探测已勾选的门禁，**连上哪个就直接开哪个**：

- 探测过程使用"单个门禁探测时间"（默认 2 秒）
- 一旦连上，**不重新连接**，直接在同一连接上走开锁流程
- 开锁成功 → 立即结束，不进入轮询
- 开锁失败 → **跳过剩余探测**，直接交给轮询兜底
- 全部未命中 → 交给轮询兜底

**为什么用"连接探测"而不是"广播扫描"**：平安回家等门禁不广播 BLE 广告包，无法用扫描发现。改用主动连接探测，能连上就说明在附近。

#### 阶段二：轮询（保底）

如果探测阶段没能开门，自动从头开始按用户排序依次尝试：

```

门禁 1
↓
失败
↓
门禁 2
↓
失败
↓
门禁 3
↓
成功 🎉
↓
立即停止

```

一旦某个门禁成功开锁，就会立即停止继续尝试。

#### 进度显示

探测和轮询共用**一条进度条**，两段各占一半：

| 阶段 | 文字 | 进度条 |
|------|------|--------|
| 探测 1/3 | `正在探测门禁 1/3: 家里` | 16.7% |
| 探测 2/3 | `正在探测门禁 2/3: 公司` | 33.3% |
| 探测 3/3 | `正在探测门禁 3/3: 小区东门` | 50% |
| 轮询 1/3 | `正在轮询门禁 1/3: 家里` | 66.7% |
| 轮询 2/3 | `正在轮询门禁 2/3: 公司` | 83.3% |
| 轮询 3/3 | `正在轮询门禁 3/3: 小区东门` | 100% |

一条线从 0% 平滑走到 100%，不重置。

### ☑️ 门禁勾选

每个门禁都可以单独控制是否参与一键开锁。

例如：

```

☑ 家里
☑ 公司
☐ 小区东门
☑ 小区西门

```

只有勾选的门禁才会参与探测和轮询。这样可以避免删除暂时不用的门禁，同时保留完整配置。

---

### ↕️ 门禁自由排序

可以自由调整门禁的探测和轮询顺序。

例如：

```

1. 家里
2. 公司
3. 小区东门
4. 小区西门

```

调整后：

```

1. 小区西门
2. 家里
3. 公司
4. 小区东门

```

探测和轮询都会按照当前排序依次尝试。因此可以把最常用、最可能成功的门禁放在前面，减少等待时间。

---

### 📊 开锁实时进度与用时

相比单纯显示「开锁成功 / 失败」，本项目增加了更加详细的开锁过程反馈。

#### 开锁过程实时状态

```

准备开锁...
↓
已连接，正在发现服务...
↓
服务发现成功，查找特征...
↓
正在读取挑战码...
↓
读取挑战码成功，正在生成指令...
↓
指令写入成功，正在开门...
↓
✅ 开锁成功

```

这样在开锁失败时，也更容易判断问题出现在哪一个阶段。

#### 开锁用时显示

无论是一键开锁还是单个门禁开锁，成功后都会弹出两个 Toast：

```

✅ 已成功开门！
（约 1.5 秒后）
用时 1832ms

```

- 探测命中成功：通常 1000~2500ms
- 轮询兜底成功：通常 4000ms+
- 单个门禁开锁：通常 1000~2000ms

### ⚙️ 开锁参数自定义

新增设置页面，可以根据不同手机、蓝牙环境以及门禁设备情况调整参数。

目前支持：

| 参数 | 默认值 | 作用 |
|------|:---:|------|
| 单个门禁探测时间 | 2 秒 | 探测阶段每个门禁的最大连接等待时间 |
| 开锁等待时间 | 5 秒 | 自动开锁时等待蓝牙开启的最长时间 |
| 单次开锁超时 | 2 秒 | 单个门禁完整开锁流程的最大时间 |
| 门禁切换间隔 | 100 毫秒 | 探测或轮询时，切换下一个门禁前的等待时间 |
| 结果展示延迟 | 1 秒 | 开锁结果展示时间 |
| 状态复位延迟 | 1 秒 | 开锁状态恢复时间 |

**参数说明**：

- **单个门禁探测时间**：探测阶段每个门禁最多等多久。信号弱时可调大，多门禁时可调小
- **开锁等待时间**：蓝牙未开启时，等待用户打开蓝牙的时间。单门禁开锁和一键开锁共用
- **单次开锁超时**：蓝牙开启后，完整开锁流程（服务发现 + 挑战响应 + 写指令）的时间上限
- **门禁切换间隔**：探测和轮询共用，两个门禁之间的保护性等待

同时提供 **「恢复默认」** 按钮，可以一键恢复所有参数。

## 📱 多门禁管理

支持同时保存多个门禁设备。

每个门禁可以单独设置：

- 名称
- MAC 地址
- 加密 Key
- 是否参与开锁
- 开锁顺序

例如：

```

🏠 家里
MAC: XX:XX:XX:XX:XX:01

🏢 公司
MAC: XX:XX:XX:XX:XX:02

🚪 小区东门
MAC: XX:XX:XX:XX:XX:03

```

可以随时添加、编辑、删除。

## 📲 二维码配置同步

支持将门禁配置导出为二维码。

### 导出

1. 点击「导出配置」
2. 自动生成二维码
3. 可以保存到相册
4. 也可以直接分享

### 导入

打开「扫描导入」，扫描二维码即可恢复门禁配置。

支持两种模式：

- **替换全部**：清除当前门禁配置，使用二维码中的配置。
- **追加到现有**：保留当前配置，将二维码中的门禁追加到列表。

## 🖼️ 桌面小部件

支持多种尺寸的 Android 桌面小部件。

| 尺寸 | 功能 |
|------|------|
| 中号 | 快速开门 |
| 大号 | 广州塔主题 + 快速开门 |
| 特大号 | 同时显示 3 个门禁并快速开门 |

特大号三键小部件可以直接展示三个常用门禁：

```

┌──────────────────────┐
│  家里       🔓 开锁  │
│  公司       🔓 开锁  │
│  小区       🔓 开锁  │
└──────────────────────┘

```

无需打开 App 即可快速开门。

### 桌面小部件增强

- **ColorOS 风格配色**：解锁按钮使用 ColorOS 绿色，与主界面视觉统一
- **深色主题适配**：浅色/深色模式下文字和背景自动适配，清晰可见
- **点击无反应修复**：修复特大号小部件点击无响应的问题
- **点击后可看到实时开锁状态**：弹出 `ShortcutActivity` 转圈界面，文字逐步更新到"✅ 开锁成功"
- **开锁完成后自动返回桌面**
- **容错处理**：特大号小部件缓存的门禁 ID 失效时，自动 fallback 到第一个有效门禁
- **连续点击防护**：`singleTop` 防止快速点击启动多个实例

## 🔄 旧数据自动迁移

如果你之前使用的是旧版 **SafeBaiyun**，本项目支持将原来的单门禁数据自动迁移到新的多门禁数据结构。

无需重新手动录入。

## 🔐 隐私与数据安全

本项目的核心开门流程采用本地蓝牙 BLE 通信。

正常开门过程中：

- 不需要联网
- 不依赖远程服务器
- 门禁配置保存在本地
- MAC 地址和 Key 不上传服务器

> ⚠️ **请妥善保管你的门禁 MAC 地址和加密 Key。**
>
> 二维码导出的配置包含门禁相关信息，请不要将包含真实门禁配置的二维码公开发布或分享给不可信的人。
